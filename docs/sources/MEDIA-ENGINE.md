# 媒体引擎持久图片任务：实施说明

媒体引擎专用分组的图片请求走一个持久任务引擎，其余分组保持原版的请求、流式、重试和结算实现。设计理由见 [ARCHITECTURE](ARCHITECTURE.md)；引擎模块说明见 [extensions/sources-media-engine](../../extensions/sources-media-engine/README.md)。

## 边界

在原版异步提交/查询处增加显式的媒体引擎分支。引擎与 Main 同进程，通过原生资金边界结算，**不是持有管理员余额权限的独立 HTTP 服务**。SQLite 放在独立的持久卷上，主库没有新增媒体引擎私有业务表或字段。

serving 进程以生产端（producer）方式打开存储，只能创建、读取和列出任务；唯一的 background 进程持有引擎锁，负责修复、执行、结算、保留和管理员处置。

## 代码职责

| 部分 | 实现 |
|---|---|
| 独立状态机、协议、SQLite WAL | `extensions/sources-media-engine`；AES-GCM 记录、版本 CAS、唯一上游回执、单 writer 锁、索引分页调度与退避 |
| Main 最小钩子 | `sources_media_engine*.go`；固定分组/账号白名单、复用原版调度/权限/原生定价/资金原语 |
| 原生资金终态 | `sources_image_ledger.go`；同事务锁定原 hold，capture 与 release 互斥、原生用量额度去重 |
| 对象引用 | 保存原存储身份和 key；提交前给参考图换签，查询结果时给原对象换签；普通交付不变 |
| 工作台 | 专门的媒体引擎 JSON 适配；普通组仍走原版 multipart/JSON；提交前存幂等标识，202 丢失只 GET 查原任务 |
| 管理核验 | `/admin/image-tasks`；原版管理员鉴权、TOTP step-up、确认与审计；不允许任意输入退款金额 |
| Portal | 与 Main 使用同一外部引擎配置；Gemini 媒体引擎分组可见，模型/参考图/遮罩能力明确 |

## 关键合同

- 外部注册表 `group_id / engine / models / account_ids`。专用组固定 `media`（已有数据的部署使用其旧引擎值，见“已有数据的部署”），其余 `sub2api`。已有任务及幂等重试按已存引擎处理。
- `account_ids` 是显式异步账号白名单，不是把组内所有 API 账号自动认成媒体引擎；同组的同步账号不进入异步兜底。
- 使用原生 OpenAI/Gemini 调度，最终再验证白名单。没有可用异步账号则报错；不提交另一引擎。
- 任务记录容量与上游在途并发分开：上游账号 `concurrency` 约束持久生成槽位；HTTP 槽位另由原生并发服务控制。未知 POST 保留生成槽位等待核验。没有“每用户最多 8 个任务”的限制。
- 报价优先复用原生公开模型价卡、分组图片价、渠道价顺序。仅无公开配置时使用媒体引擎内部价卡默认价；受理时冻结价格快照，后台不按后来价格重算。
- JSON 单任务 n=1；参考图最多 4 张；不支持 mask/stream；工作台多图拆独立任务。普通分组参数不受这些限制。
- `admitting → queued → submitting → running → settling → downloading → completed`。生成成功先结算，再交付；下载失败不变成免费重新生成。
- 上游 POST 从意图写入开始不自动重发；网络结果未知、持久化后续状态失败或进程中断进入 `unknown`。管理员绑定核实过的上游任务，或确认未成功后释放原预留。
- 24 小时仍未真正发出上游请求的队列任务释放其原 hold；已发出但结果未知的任务不自动释放。交付重试不改原创建时间。
- 可选的自动收尾策略（默认关闭，需策略文件与单独的启用标记同时匹配）：有上游任务号的只查询；超过期限且没有成功证据的 `unknown` 任务按原冻结释放客户余额，供应结果仍记为未知，晚到的结果不再扣费。细节见 [引擎说明](../../extensions/sources-media-engine/README.md)。
- 完成/失败载荷保留 7 天后脱敏成幂等墓碑，墓碑保留至终态后 30 天；未解决资金任务不按时间删除。客户端不得把旧幂等键当新业务请求重复使用。
- SQLite 与 PG 不构成分布式事务：通过可重试的持久任务状态和原生确定回执闭合；余额/冻结款、Key/账号额度在 PG 的同一事务中处理；用量日志失败仍会重试。

## 原版问题单独记录

原生用户×平台配额使用“PG 扣费提交后，Redis 更新/异步持久化”。进程在这两步之间中断仍可能漏计平台额度；本次复用其语义，没有悄悄引入另一套计费账本。资金扣减/释放本身不受该窗口影响。启用该限制时必须明确处理这一窗口，不能把该计数宣称为持久 exactly-once。

## 运行配置

Main 环境变量：

```text
SOURCES_IMAGE_ENGINES_FILE=/run/sources/image-engines.json
SOURCES_MEDIA_ENGINE_KEY_FILE=/run/secrets/media-engine-master.key
SOURCES_MEDIA_ENGINE_DATA_DIR=/var/lib/sources-media-engine
```

### 已有数据的部署：`SOURCES_MEDIA_ENGINE_LEGACY_NAME` 与 `SOURCES_MEDIA_ENGINE_LEGACY_TASK_PREFIX`

引擎的名字写进了多处已持久化或跨进程的值：任务存储的密封校验值、资金命令的幂等请求号前缀、内部价卡模型路径、对象存储 key 前缀、注册表与 Studio 客户端使用的引擎值；任务号前缀另写进了任务存储、资金账本的 batch id，并经 API 返回给客户端。公开代码只含中性值（名字 `media-engine`，引擎值 `media`，任务号 `mediatask_<32 位 hex>`）。已经用早期值写过这些数据的部署，必须在私有配置中设置：

```text
SOURCES_MEDIA_ENGINE_LEGACY_NAME=<旧引擎名>          # Main 与 Portal
SOURCES_MEDIA_ENGINE_LEGACY_TASK_PREFIX=<旧任务号前缀>  # Main；不含末尾的下划线
```

- 旧引擎名须匹配 `^[a-z0-9]{2,32}$` 且不能是 `sub2api`；旧任务号前缀须匹配 `^[a-z0-9]{2,16}$`。两者描述同一个已有部署，必须同时设置或同时不设，只设一个时 Main 启动报错（错误只列出两个变量名）。校验失败时错误信息不回显取值。只能经环境变量设置，配置文件不能设置。
- 设置旧前缀后新任务号仍是 `<旧任务号前缀>_<32 位 hex>`；任务查询路由、存储读取、恢复策略中的历史任务号与账本 batch id 检查同时接受旧前缀与 `mediatask`。资金请求号、对象 key 都内嵌完整任务号，自动随之一致。
- 设置后，上述每个值都与早期版本在同一位置写出的值逐字节相同；读入时旧值与中性值都接受（注册表可写 `media` 或旧值，Portal 返回给 Studio 客户端的始终是旧值）。
- 未设置（全新安装）时只使用中性名。已有数据却漏设时不会静默以空状态运行：注册表中的旧引擎值报 `unsupported image engine`，旧任务存储报 `task store identity or key check failed`，进程都拒绝启动；漏设任务号前缀则配置校验失败。
- 该值是私有运营信息，只放在服务器配置里，不写入本仓库、测试或文档；测试使用明显虚构的 `legacyname`。

Portal 的 `STUDIO_CONFIG_FILE` 指向同一注册表文件（同版本只读挂载）。管理员配置文件，不能接受普通请求传入引擎。实例启动时加载；修改配置时保留当前任务数据卷并受控重启。原生（`sub2api`）分组还可以由管理员在 Portal 页面内在线登记，不经过本文件，也不需要重启；媒体引擎分组只能在本文件里配置，在线登记不能新增或修改它们，见 [Portal 说明](../../extensions/sources-portal/README.md)。

主密钥为 32 字节随机值的 64 字符 hex 文件，权限 0600；数据目录 0700。不得提交真实密钥/账号凭据。只有后台进程持有该卷的引擎锁；第二个引擎启动会明确失败，不会重复运行任务。

对象存储使用原生 S3 设置。媒体引擎输入/结果按独立 prefix 保留；生命周期至少覆盖任务恢复窗口，**不要对共用备份 bucket 全局加过期规则**。切换存储 endpoint/bucket 前必须处理原任务依赖，旧对象不会自动迁移或指向新桶。

## 测试覆盖

- 引擎与 Main 的 race 测试：请求参数、原生定价优先级、平台额度后处理、不重复扣减余额缓存、原版异步 handler、CORS、幂等、SQLite CAS/加密/重启、未知提交、分页公平性、互斥上游回执、保留期、生成槽位、对象换签。
- 真实 PostgreSQL：多任务冻结；capture 与 release 竞争；迟到的 release 不消耗另一任务的冻结款；额度更新失败时 capture 与回执一起回滚；重建仓储后重试只结算一次。
- 工作台：提交前持久化标识、丢失 202 后只查询原请求、刷新、凭据变化拒绝、存储失败不发 POST。
- 管理端：确认与取消、只绑定原上游任务、金额不可编辑、交付阶段只允许重试交付。
- 隔离的 Main API 联调：使用 TLS 媒体引擎上游与 S3 模拟服务，覆盖成功、失败释放、幂等冲突、丢失 202、跨组拒绝、停用账号不兜底、重启和 Key 撤销，确认重复查询与重启不增加上游 POST。

## 回退

应用回退必须保留**当前** PG、Redis 任务状态、SQLite/WAL 和对象存储新增写入。先停新增媒体引擎任务，排空/核验已接受任务；旧版本不认识新任务时不得直接停止唯一处理者。未排空就取消本次切换，或保留限定的当前查询/处理入口；不得恢复旧 SQLite/旧主库来覆盖新账单与余额。

备份应覆盖 SQLite 的一致性快照及主密钥；直接复制运行中单个 `.sqlite` 而不处理 WAL 不算有效备份。上线前应完成在线快照与恢复演练。
