# 扩展架构：以升级原版的成本为约束

本文说明二开代码放在哪里、为什么这样放。具体能力见 [SOURCES](../../SOURCES.md)。

## 决策顺序

1. 原版设置能表达：使用设置，不改源码。
2. 原版标准 API 能完成：在独立模块调用，不访问 Sub 私有数据库。
3. 外部适配：保持明确的协议、持久化和故障边界；不为每个页面增加一个服务。
4. 必须进入核心：只保留一个明确的挂接点并复用原版内部能力，逐文件登记、配契约测试和独立回退。没有证据的“纯插件化”不作为承诺。

## 所有权

| 能力 | 唯一所有者 | 核心接入 |
|---|---|---|
| 登录、账号、分组、调度、Key、价格、计费、充值账本 | 原版 Sub | 不复制实现 |
| 渠道监测 20/60 秒 | 原版 V1 monitor + 参数小补丁 | 原 settings、校验、每轮快照；不另建探测服务 |
| Logo、主题色、深浅色 | 原 Logo 设置 + 轻量浏览器主题模块 | 8 套配色、CSS 变量、旧本地偏好键；首页与控制台同源同步，无新数据库字段 |
| 首页、内容编辑、上游余额、工作台授权、智商检测 | 一个 Sources Portal 进程 | 原 `home_content`、自定义菜单和用户/管理员 API |
| 外部价格协议 | 独立 Sources Pricing Feed 进程 | 只读公开模型广场 API，白名单输出和持久快照；不进入计费链路 |
| 工作台画布、本地历史、202 轮询 | 独立客户端 | 原 API；按主站 + 用户隔离本地存储；切组保留已有任务授权 |
| 福利中心 | 已有福利系统 | 首页只导航；身份与钱包映射不变 |
| 媒体引擎任务 | 独立任务引擎 + Main 原生资金挂接 | 原版异步缺少持久任务能力；只给媒体引擎专用分组加最小持久任务桥，普通异步保持原实现 |
| USDT 链上状态 | BEpusdt | 小型原生 provider + 集中的付款确认边界；不为少改代码降低资金防线 |

“一个 Portal 进程”不意味着把模型请求、支付或用户余额塞进一个 HTTP handler。媒体和支付模块使用独立的包、路由和凭据边界；只有实际需要的 worker 才运行。

## Portal 的设计要点

- 品牌层提供 8 套本地配色；色板和偏好控制器由首页与控制台共享。首页和编辑数据都在扩展目录中。
- 余额、首页与工作台入口共用身份校验和受限的 Main API client，没有第二套角色判断。
- Portal 使用与 Sub **同源的固定扩展路径**，只读原版 `auth_token`，不持有 refresh token，不复制登录/注销逻辑。跨标签 `storage` 事件联动注销；用户切换会锁定旧编辑器和画布。
- 身份请求保留可信入口的 IP/UA，不信任外来的 `X-Forwarded-For`。JWT 未验签字段的预检只用于提前拒绝不一致的请求，最终由 Sub 验签。
- 画布使用独立 origin，iframe 只接收普通模型 Key，不能读取 Main 登录存储；静态文件可由同一 Nginx 提供，不多拆业务服务。
- 工作台只以当前用户身份调用原 Key API：每人每组生成一个**普通、可见、可撤销、30 天有效**的 Key；外部只保存绑定 ID 和创建操作号，不保存用户 JWT 或 Key。
- Key 创建结果不明时先查原记录，**不自动再次 POST**。已停用、删除或过期的 Key 不静默换成新 Key。
- 按用户/分组的可取消锁隔离并发；磁盘锁不覆盖网络 I/O。
- 服务端内容与授权配置共用原子写组件。rename 后目录 fsync 失败时，内存与磁盘版本保持一致并停止后续写入，重启后核对，不吞掉不确定的提交。主题偏好只在浏览器保存。
- 内容是结构化数据，由 Vue 文本绑定渲染，不接受可执行 HTML 或脚本；草稿与发布历史分离，历史恢复先回到草稿，CAS 防止覆盖他人编辑。
- 所有鉴权响应解析后的会话复核集中在共享的 `authorizedJSON` 中，并覆盖退出期间迟到响应的情况。

## 媒体引擎：必要的核心例外

原版异步图片只保存任务结果和归属，执行在进程内 goroutine 中，不保存可恢复的请求或上游任务引用；`X-Client-Request-ID` 不直接采纳客户端值；普通 Images 的用量记录进入内存队列，HTTP 200 不是确定的结算回执。因此“同步适配器等待媒体引擎完成”不是完整的任务迁移。实现的边界是：

- 媒体引擎专用分组的 Submit/Get 挂接；普通分组仍走未改动的原版异步。
- 外部持久任务记录固定 owner、Key、账号、请求指纹和上游引用；提交结果未知时冻结待核对，不自动重新生成。
- Main 负责原版准入、价格快照和确定结算；外部没有余额管理权限，也不能上报任意扣款金额。
- 复用原版 `usage_billing_dedup` 的 `(request_id, api_key_id)` 幂等，并明确“完成/补齐”语义，而不是把普通 RecordUsage 包一层当作结算。

原版公开的插件协议目前只覆盖 OAuth outbound transport（见 `docs/PLUGIN_DEVELOPMENT.md`、`backend/pkg/pluginapi/`），不是通用的持久任务或确定结算插件。若原版以后提供相应能力，应优先替换媒体引擎挂接，而不是维护两套同义入口。实现细节见 [MEDIA-ENGINE](MEDIA-ENGINE.md)。

## USDT：按真实协议验证

[BEpusdt 兼容说明](https://github.com/v03413/BEpusdt/blob/main/docs/api/other.md)声明支持 `submit.php`，但原版 EasyPay 还依赖 `api.php` 查单，所以不能仅凭该说明判定完整兼容。主动查单、唯一付款凭证、配置版本绑定与持久补偿不是收银台装饰，而是资金防线：

- 先保证资金语义，再减少代码：UI 可以简化，付款核验和幂等保障不能退出。
- 新单与历史单共用唯一的业务订单、付款凭证和履约入口；不另造外部余额账本，不用管理员加余额 API 代替充值履约。
- 使用小型 BEpusdt 原生 provider，并在 Main 中保留集中、可测试的付款确认事务挂接；不搬旧的私有支付 UI、订阅升级或 worker 架构。
- 复用 `payment_receipts`、`payment_provider_versions` 与订单记录；“保留表”必须同时验证代码仍在执行相应约束。

实现见 [PAYMENT-IMPLEMENTATION](PAYMENT-IMPLEMENTATION.md)。

## 原版认证行为

原版普通注销和 revoke-all-sessions 清理 refresh session，现存 access JWT 仍可能有效到过期；修改密码后旧 JWT 失效。本仓库保留原版后端行为，不把扩展的定期 `/auth/me` 检查说成即时撤销。同源页面的退出由共享 token 删除事件联动；若需要 API 层即时注销 access JWT，应另向原版提出。

## 升级门禁

- 固定基线 SHA，维护逐路径、逐哈希的核心差异清单；禁止笼统豁免 `backend/` 或 `frontend/` 目录。
- 新原版版本先独立运行契约：身份和角色、会话绑定、普通 Key 的创建/查询/撤销、分组可见性；随后做图片、支付协议与故障验证。
- 运行原版未改动部分的上游测试；扩展测试单独执行。新 API 兼容性未通过时，不自动回落到旧私有路径。
- 不新增私有业务字段；不修改迁移账本 checksum；保留旧私有表不等于恢复其业务。
- 每个挂接写明职责、契约测试、回退方式，以及被原版替代后的退出条件。

主题的实现与验证见 [THEME-PREFERENCES](THEME-PREFERENCES.md)。
