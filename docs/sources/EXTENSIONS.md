# 从旧私有分支迁移的保留与退出范围

本仓库最初从一个在旧原版上累积了大量私有改动的分支重建：以较新的原版为核心，只把确认需要的能力用小补丁或外部模块重新实现。本文记录当时确定的范围，原则是**保留项能力不缩水，退出项不复活**。现行能力以 [SOURCES](../../SOURCES.md) 为准。

旧分支的路径差异数包含测试、文档、生成代码和运维文件，**不等于功能数**，也不意味着每个路径都要搬过来。

## 保留什么、放在哪里

| 能力 | 新实现位置 | 必须保留的体验或结果 |
|---|---|---|
| 登录、用户、普通 Key、账号与分组 | 原版核心 | 老用户登录、原 Key 调用、权限边界、价格和余额语义 |
| 品牌主题色、Logo、深浅色 | 共享 CSS 变量 + 本地偏好 + 原 Logo 设置 | 8 色选择器、移动端、深浅色、首页与控制台同源同步；见 [THEME-PREFERENCES](THEME-PREFERENCES.md) |
| 首页 | 外部页面，接入原版 `home_content` | 首屏、公告、卖点、联系方式与二维码、价格表、介绍、页脚、动效和响应式布局 |
| 首页内容管理 | 外部管理员编辑器 | 编辑、预览、发布、版本恢复；服务端校验管理员；配置不进主库 |
| 签到卡片 | 首页展示组件 | 日历动效；按钮固定为“前往福利中心”，不发签到请求，不显示伪造的奖励状态 |
| 福利中心 | 现有独立福利系统 | 登录后进入，历史身份和积分不重新绑定 |
| 图片工作台 | 独立客户端 + 最小身份接入 | 免填 Key、分组与模型选择、生成与编辑、参考图、预览下载、历史恢复、参数约束 |
| 普通异步生图 | 原版 async / Redis / S3 | 提交 202 → 查询 → 结果；同 Key 归属；刷新页面不重新提交 |
| 媒体引擎异步 | 独立任务引擎 + 专用原版分组 | 支持的模型、尺寸、质量、参考图，多图拆分，幂等恢复，单次结算；见 [MEDIA-ENGINE](MEDIA-ENGINE.md) |
| 人民币充值 | 原版支付 + 必要的资金核验边界 | 订单、支付状态、到账、历史订单读取，重复通知不重复到账 |
| USDT | BEpusdt + 小型原生 provider 与集中确认挂接 | 可用链、币种、金额、收银台、查单、迟到或重复回调；见 [PAYMENT-IMPLEMENTATION](PAYMENT-IMPLEMENTATION.md) |
| 上游余额监测 | 原生账号列与抽屉 + Portal 只读查询与缓存 | 一个来源绑定多个账号、同站多钱包、币种与成功时间、过期状态；不以模型 Key 限额代替钱包；见 [UPSTREAM-BALANCE](UPSTREAM-BALANCE.md) |
| 渠道主动监测 20/60 秒 | 原版监测上的参数补丁 | 成功 <20 秒绿、≥20 秒黄，失败或超时红，总超时 60 秒，调整后下一轮生效 |
| 原版“使用密钥”与“导入到 CCS” | 原版原文 | 保留官方入口和隐藏 CCS 的管理员设置 |
| 运维 | 原版运行方式 + 外部发布、备份工具 | 固定构建、健康检查、恢复、后台任务交接、观测、回退；见 [DEPLOY](DEPLOY.md) |

“功能一样”按完整业务结果验收，不要求复刻旧故障或内部实现。例如工作台改用普通、可撤销的 Key 是有意的授权方式变化，必须明示，不能当作无差别。

## 旧私有功能的去留

| 旧范围 | 处理 | 数据与兼容 |
|---|---|---|
| 账号/分组增强、私有调度、池路由、冷却/亲和/回退 | 由原版替代，不复制旧状态机 | 保留 ID、绑定和价格；旧路由触发器单独退出 |
| 注册来源规则、通行码、强制邀请码、返佣 | 不迁移；原版不用的功能关闭 | 老密码和 OAuth 身份不重建；优惠码仍是独立功能 |
| 订阅升级、差价报价、续期定制 | 不再销售，不迁移 | 历史订单与既有权益保留 |
| 站内签到接口、奖励和配置 | 退出业务实现，只留卡片与导航 | 福利系统的资产和身份不变 |
| 复杂主题注册、favicon/菜单 hook | 只提取需要的 UI 和资源 | 不带入多主题管理 |
| 托管工作台会话与隐藏 Key | 外部最小接入 + 普通可撤销 Key | 旧 Key 先核对在途任务和用途再分阶段退出 |
| 私有 URL/Base64 包装、代理返图、JSON/SSE 桥接与特殊结算 | 普通路径回到原版 | 旧链接先停止签发再按有效期退役；不删历史图片 |
| 媒体引擎原生任务、worker、下载 | 独立引擎保留必要能力 | 不在主库加私有表或余额账本；重启恢复和幂等是硬要求 |
| Grok 图片/视频定制、旧协议与历史任务包装 | 新请求使用原版 | 存量任务单独收尾，不靠删除任务完成迁移 |
| 第三方协议补丁、工具 ID 兼容、额外 keepalive/failover | 由原版替代；发现原版问题单独报告 | 用模拟上游测试兼容差异 |
| 私有支付弹窗与收银台 | UI 简化 | 原生核验、唯一凭证、旧单配置版本和持久补偿必须等价承接 |
| 隐式价格倍率兼容 | 不搬隐式补丁，改为原版显式配置 | 上线前验证价格不变，不补扣历史 |
| 旧私有导入向导与下载适配 | 退出 | 原版导入协议保持原文 |
| Ops 路由轨迹、用量聚合、分析库 | 原版查询 + 按需外部分析 | 用量事实保留 |
| 安全审计、IP 策略、SMTP 错误包装 | 采用原版和外部防护 | 单独核对现行策略，减少代码不等于保持防护 |
| 私有 schema、Ent 生成物、迁移账本 | 保留数据库兼容结构，不复制私有业务模型 | checksum 不改，旧表不硬删，扩展不加主库字段 |
| 私有 serving/worker、蓝绿与镜像更新 | 重新实现为 serving/background 角色与固定槽位发布 | 后台唯一所有权需要交接 |

## 迁移时需要特别注意的差距

1. **工作台与 202。** 旧客户端把 202 当作最终图片结果；新客户端需要轮询和持久化任务 ID，并在登录、下载、刷新、撤销 Key 等场景联调。
2. **原版异步不是持久 worker。** 原版每次提交新建 ID 并在进程内执行，没有客户端幂等键；媒体引擎之外的普通异步在进程重启后不会恢复。不要用 prompt 哈希合并用户正常的重复创作。
3. **旧工作台凭据。** 原版不识别旧凭据的用途限制，登录成功不代表权限等价。
4. **历史用量类型。** 旧私有的请求类型在原版界面中的显示含义可能不同；数据仍在不代表展示语义相同。
5. **付款协议。** 兼容 `submit.php` 不能证明查单、迟到通知等语义等价。

后续新增保留项时，先登记来源、目标接口、测试和运维责任，不再“顺便搬一大块旧代码”。逐项验收场景见 [PARITY](PARITY.md)。
